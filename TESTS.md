# Tests

Run tests through `bun run ...` from the repo root.

| Command                                                                                                                                                                                                                                                                                                                                                         | What It Checks                                                            | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `bun run test:bun`                                                                                                                                                                                                                                                                                                                                              | Server, scripts, utilities, and core TypeScript tests                     | Uses `scripts/runBunTests.ts`; best default for backend changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `bun run test:vitest`                                                                                                                                                                                                                                                                                                                                           | App/component tests that use Vitest                                       | Use for client-side unit tests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `bun run test:playwright`                                                                                                                                                                                                                                                                                                                                       | Browser smoke and e2e tests                                               | Starts the app/server through Playwright config.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `bun run test:network-smoke`                                                                                                                                                                                                                                                                                                                                    | Current primary DB route/network smoke                                    | Read-only/mutation-limited current DB audit. Catches broken pages, API failures, API-role DuckDB ownership, fatal DuckDB restarts, worker loop failures, forbidden server runtime logs, and failed/stalled/unqueueable review-warning states, including terminal failed V4 rebuild requests with queued downstream chunks. Queued V4 warning states must expose claimable work and make progress after a bounded retry when mutations are enabled; mutation-disabled current DB runs may report blocked pending backlog without claimable queued work. |
| `bun run test:network-smoke:current-db`                                                                                                                                                                                                                                                                                                                         | Same as `test:network-smoke`                                              | Explicit current-DB alias.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `bun run test:network-smoke:synthetic`                                                                                                                                                                                                                                                                                                                          | Synthetic DB route/network smoke                                          | Safer isolated smoke when current DB data is not needed. Also checks forbidden server runtime logs.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `bun run test:dev-server:current-db`                                                                                                                                                                                                                                                                                                                            | Real `dev:server` startup against the primary DB                          | Captures server output and fails on API-role DuckDB ownership, fatal DuckDB restarts, owner heartbeat errors, worker loop failures, and mutation-enabled review-serving work that stays queued without maintenance progress. Stops the dev server when done.                                                                                                                                                                                                                                                                                           |
| `bun test src/server/utils/duckdbServiceReload.test.ts src/server/utils/duckdbServiceShutdown.test.ts src/server/utils/duckdbServiceMemoryLimit.test.ts`                                                                                                                                                                                                         | DuckDB lifecycle, WAL recovery, and low-memory checkpoint regressions      | Covers startup WAL replay quarantine before in-process DuckDB open, fatal runtime restart containment, signal/explicit shutdown checkpoint behavior, low-memory checkpoint thresholds, and serialized low-memory write lanes.                                                                                                                                                                                                                                                                                                                            |
| `bun test src/db/migrateDuckdb.test.ts src/server/reviewServing/reviewServingSchema.test.ts`                                                                                                                                                                                                                                                                    | DuckDB migration and review-serving V4 schema drift checks                | Catches already-applied current-DB V4 mart drift such as missing `payload_kind` before worker chunks hit binder errors.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `bun test src/server/reviewServing/reviewServingV4RebuildRequestService.test.ts src/server/workers/reviewServingProjectorWorker.test.ts src/server/reviewServing/reviewServingRebuildRequestRepository.test.ts src/server/reviewServing/reviewServingChunkManifestRepository.test.ts src/server/routes/projectsRoutes/projectsRoutesGetReviewsWarnings.test.ts` | V4 rebuild request admission, chunk re-admission, and warning diagnostics | Covers candidate-only missing-snapshot bootstrap chunking, bounded selected-import/summary/bootstrap chunks, runtime DuckDB OOM splitting for article-range rebuild chunks, selected-import range execution, operator re-request after terminal failed V4 rebuilds, reset of stale request failure metadata and retryable chunk execution metadata, and real-DuckDB reclamation of expired `projectScope` prerequisites before downstream V4 chunks.                                                                                                   |

Target a single Bun test file with `bun test path/to/file.test.ts`.

Quality gates: run the narrow test for your change first, then `bun run lint` or `bun run build` when the changed layer needs it.
